## What the toolset is missing

**`PowerShell` — 16 attempts, third consecutive run reporting the same count.**
The previous two fixes ("record it, don't work around it") changed nothing
because neither wrote down _what to do instead_. Task 1.2a needed it concretely:
stopping the dev server took three attempts — `pkill -f "next dev"` exited
cleanly and killed nothing, a `Get-Process | Where CommandLine` filter matched
nothing, and only `Get-NetTCPConnection -LocalPort 3000 -State Listen` worked.
That route now exists in a transcript and nowhere else.

**Bash displacing the dedicated tools:**

| Anti-pattern               | Count | Trend   | Against        |
| -------------------------- | ----- | ------- | -------------- |

Every count rose. `cd` prefixing is up 42 occurrences and remains at a third of

Task 1.2a hit the consequence twice. Once benignly: `cd packages/db` failed
because the shell had reset to `apps/web`. Once not: `rm -f apps/web/src/spike-adapter.ts`
ran while the shell sat in `packages/db`, deleted nothing, exited 0, and `&&`
printed "spike removed" — a false confirmation that survived until a later `ls`
contradicted it.

## Fixes

1. **Treat `WebFetch` and `WebSearch` as unavailable.** 31 calls, 0 successes.
   Record in `docs/13-agent-tooling.md` that both are blocked here (domain
   verification fails; two were refused for trust mode outright). Use `context7`
   for library docs — 1 call, 1 success — and ask the user to paste content
   otherwise.
2. **Never pass a relative path to Bash.** Not "prefer absolute": the 332 `cd`
   calls and 18 `File does not exist` errors are one defect. Replace
   `cd packages/db && npx prisma …` with an absolute `--schema` path.
3. **Never `&&` a success message after `rm -f`.** `rm -f` on a missing path
   exits 0, so the chained message lies. Use `rm -v`, or verify separately. This
   produced a false verification this window.
4. **Write the PowerShell route down, stop re-flagging the gap.** Add to
   `docs/13-agent-tooling.md` § 1.1: Windows process/port work goes through
   `powershell.exe -Command "…"` inside Bash, with
   `Get-NetTCPConnection -LocalPort N -State Listen | … Stop-Process -Force` as
   the worked example. Three runs of "16 attempts" is enough.
5. **Enforce the two-failure rule with a hook, not a rule.** It is documented and
   was violated at 9 repeats. A `PreToolUse` hook keyed on repeated identical
   `(tool, error-signature)` pairs is the only version of this that can work,
   because the rule depends on the judgement that just failed.
6. **Leave the 136 environmental errors alone.** Recording them as not-ours is
   the fix; they are not a backlog.
