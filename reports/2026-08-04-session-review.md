## Fixes

1. **Add warn-level hookify rules for the top-3 displacement patterns.** Match
   bare `cat`/`head`/`tail` and bare `grep`/`find` in a `Bash` command only when
   the command is a plain read (no pipe, no flags needing a stream) and warn to
   use `Read`/`Grep`/`Glob`. Warn, not block — `cat | jq` must survive. Then
   measure next window's violation count: enforcement tracks the _ranked_
   anti-pattern list, top-down. **Status: implemented this session** —
   `.claude/hookify.bash-instead-of-{read,grep,glob}.local.md` (all `warn`);
   the next full window measures whether the counts fall.
2. **When a hook lands mid-window, record its start time in the report.** The
   10-denials-vs-1498-violations split is a 2.7 h-old hook, not a broken one;
   the next full window is the first real measurement. (Method note, no code.)
3. **Drop the PowerShell hook idea — it is not hookable.** The
   `No such tool available: PowerShell` error is a _tool-call_ error, not a bash
   command or file edit, so no hookify rule can see it (a `bash` rule matching
   `powershell` never fires — the model never types it into Bash, which is the
   whole problem). A `PostToolUse` rule cannot work either: it fires only after
   a _successful_ call, and a nonexistent tool never succeeds. The only lever is
   the § 3.6 route (`powershell.exe -Command "…"` inside Bash) — keep it as a
   documented route, surface it in the model prompt, and stop proposing a hook.
4. **Narrow § 3.8 to `WebFetch`.** Update `docs/17` § 3.8: `WebSearch` works now
   (5/7); keep the context7 rule, drop the "WebSearch dead" claim.
5. **Read before Write stays the KPI.** The harness guard fires (×6) but the
   model re-attempts; § 3.5 applies to Write. Before a `Write`/`Edit` of an
   existing file, `Read` it in-session. Track the guard count as the metric.
6. **Leave the 143 `model-unavailable` + 2×405 alone.** Environmental; recording
   them as not-ours is the fix.
