## What the toolset is missing

From `capabilityGaps` and `antiPatterns` — a repeated call to an absent
capability is a requirement, not a mistake:

1. **A Windows process/port tool.** `PowerShell` ×17 — unchanged across three
   runs. The § 3.6 `powershell.exe -Command` route is written down but the model
   keeps invoking the tool by name. Nothing enforces the route.
2. **A working web-fetch path.** `WebFetch` 15/15 dead (0 for 45 over three
   windows). `WebSearch` 5/7 again (2 errors of 7 this window) — marginal but
   usable for a single attempt. `context7` remains the only reliable doc route.
3. **A KPI that makes warn-hook enforcement legible.** The displacement
   anti-patterns are the largest measured defect (759 + 340 + 98 = 1197 Bash
   calls doing a dedicated tool's job), and they now have warn hooks — but the
   reported metric (absolute count) cannot move in response to a warn, so the
   hooks read as inert. This is a measurement gap, not a tool gap.

## Fixes

1. **Measure warn-hook effectiveness by displacement ratio, not absolute count.**
   A `warn` does not suppress the call — it advises — so the raw `bash-instead-of-*`
   count is structurally incapable of falling and will grow with session volume.
   The correct KPI is `bash-embeds / dedicated-tool calls` (e.g.
   `bash-instead-of-read / Read`), which fell 0.83→0.71 this window — a real win
   the absolute count hides. **Status: this is a rule, not a one-window note —
   added to `docs/17` § 3.10.** Track the ratio in the next retrospective; if it
   keeps falling, the warns work.
2. **`delegated-scribbling-dragon` (241 calls, 3 errors = 1.2%) is the
   achievable baseline.** It is the cleanest session in the window by a wide
   margin, and it did real work (a new package, a slash command, two fixes). The
   8.8% flat is being carried by the 2026-08-02/03 scaffold sessions still
   inside the 7d window; as they age out, the rate should drift toward the
   marginal ~2%. No code change — a target for the next review to check against.
3. **Leave the stable our-error buckets alone.** `path-not-found`, `missing-tool`,
   `permission-denied`, `protocol-misuse`, `timeout` all moved by ≤1 this window.
   They have rules in `docs/17` already; re-opening them adds noise. Revisit only
   if a bucket jumps next window.
4. **Keep `ExitPlanMode` the read-before-write KPI as-is.** 5 of 14 rejections is
   high but it is a user-gate firing, not a defect; the harness `protocol-misuse`
   guard (×6) is the metric that tracks our side. No change.
5. **Leave the 145 `model-unavailable` + 2×405 alone.** Environmental; recording
   them as not-ours is the fix. A single retry per outage remains the rule (§ 3.5).
